## Вывод

В socomputing есть настоящие сообщения агента, вызовы инструментов и результаты,
а также журнал гипотез с сохранёнными первичными артефактами. Особенно полезны
эпизоды **проверки обоснованности вывода, отказа от чрезмерного обобщения,
исправления verifier и признания неопределённости**.

Это перспективный четвёртый источник для корпуса Jev. Готовой разметки качества
каждого шага или оптимального следующего действия здесь пока нет. Прирост модели
от этих данных не измерен.

## 3. Проверенные примеры

### VSAR134: улучшение loss не выполняет основную гипотезу

Источники: журнал, строка 689; `artifacts/vsar134-e2-target-v5-2026-08-27/`;
`artifacts/vsar134-e2-verification-v5-2026-08-27/verified-summary.json`.

По девяти `run.json` сверены SHA256 с target manifest и пересчитаны ранги,
Recall, MRR и first-four NLL: три seed × три arm, по 256 queries.

| Seed | Δ Recall@1 plain против WikiText | Δ MRR | Относительное снижение first-four NLL |
|---|---:|---:|---:|
| 134001 | −0.00390625 | +0.003125 | 40.963% |
| 134002 | −0.01171875 | −0.001028 | 40.172% |
| 134003 | +0.015625 | +0.021162 | 41.007% |

Средний Δ Recall равен **0**, среднее относительное снижение NLL — **40.714%**.
Порог Recall +0.15 и MRR +0.10 не выполнен. Сохранённые repeated-tail ratios
также выше 0.50, а role criterion не выполнен ни на одном seed. Поэтому
зарегистрированная совокупность критериев FALSIFIED на локальном E2, несмотря
на частичное улучшение NLL. Это хороший пример для проверки подмены цели метрикой.

В сыром корневом диалоге `01a03977-6197-7d71-ad05-a123046d84ab`, строка 45727,
агент явно делает именно этот ограниченный вывод, а не объявляет успех чата.

### VSAR135: корректный ответ — INCONCLUSIVE

Источники: журнал, строка 697;
`artifacts/vsar135-prereg-prompt-sensitivity-2026-08-27.md`;
`artifacts/vsar135-e2-target-v1-2026-08-27/`.

Это диагностическая проверка тех же трёх dialogue_plain моделей и тех же 256
queries. Она сравнивает настоящий prompt с тремя перестановками prompts и null;
это не новый независимый тренировочный корпус.

| Seed | Recall authentic − mean deranged | NLL advantage, nats | Top-1 flip rate |
|---|---:|---:|---:|
| 134001 | −0.00390625 | 0.054788 | 0.119792 |
| 134002 | −0.00520833 | 0.022313 | 0.134115 |
| 134003 | −0.00781250 | 0.081196 | 0.105469 |

Основной агент независимо восстановил эти величины из `scores` и
`true_logprobs`; три run hash совпали с manifest. Frozen support требует на
каждом seed Δ Recall ≤0.02, NLL advantage <0.05 и flip rate ≤0.30. Falsification
требует хотя бы на одном seed Δ Recall >0.05 либо NLL advantage >0.10.
Support не выполнен на первом и третьем seed; falsification не выполнен нигде.
Результат **INCONCLUSIVE**. Отсутствие поддержки не следует размечать как
опровержение гипотезы.

### VSAR129 v6: узнавание знакомого не означает надёжного отказа на новом

Источники: журнал, строка 682; `artifacts/vsar129-e1-v6/raw.json`, `result.json`
и `artifacts/vsar129-e1-v6-lead-audit-2026-08-27.md`.

SHA256 raw совпадает с журналом и result:
`2eaeb76dad723f13771b5c3f4182258a20f8981e5d57d43622efdf048c31b7d7`.
Exact/NFKC/typo/morphology Recall@1 равен 1.0 на трёх seed. При этом ложное
уверенное извлечение на 64 unrelated queries — **56.25%, 50.00%, 65.625%**
при gate ≤5%. На 48 новых сочетаниях знакомых частей — 75%, 66.67%, 87.5%.

Это конкретный провал принятия unfamiliar compositions, а не доказательство
бесполезности всей HDC-памяти. Авторский audit отдельно отмечает недостатки
capacity fixture; latency из этого fixture не используется как опровержение.
Старый v5 с нулевой false rate — другая версия с другой конструкцией. Нельзя
смешивать результаты версий по одному H-tag.

### VSAR128 v6: узкий инженерный успех

Источник: журнал, строка 687; `artifacts/vsar128-e1-v6-result.json` и raw JSON.
Совпадение raw SHA и арифметика ratio проверены:
48,235 / 925,968 = **0.05209143296528606**, ниже gate 0.10.
Сохранённое replay time — 2.87231 s при gate <5 s, 100 committed turns.

58 adversarial tests и точный replay сообщаются в историческом журнале; в этом
обзоре они заново не запускались. Допустимый вывод ограничен single-writer
library E1. Из результата нельзя автоматически вывести улучшение качества
языковой модели, интеграцию ChatREPL или безопасность concurrent writers.

## 4. Исправление verifier как отдельный процессный эпизод

`artifacts/vsar134-independent-audit-v1.md` описывает дефект прежнего verifier:
внутренняя согласованность score/logprob и пересчитанные хеши позволяли принять
подделанный результат без проверки соответствия сохранённой модели.
Исторические passing tests сами по себе этот дефект не исключали.

В текущем `scripts/verify_vsar134_v3.py`, строки 177–193, oracle заново считает
каждого кандидата и generation transcript из model.npz. Поэтому старый дефект
нельзя приписывать текущей версии. В сыром корневом диалоге выше, строка 45104,
есть решение сначала устранить критичный false-acceptance defect.

Historical verification summary также сообщает top-level NotADirectoryError:
prepared_path был файлом, а проверка ожидала каталог. Текущий код содержит
`_prepared_parent`, который исправляет это преобразование. Его текущий hash
отличается от hash в историческом summary; это фиксируется как различие версий.
Свежий runtime replay текущего verifier в рамках обзора не проводился.

Это отдельные цели разметки: «надёжно ли evidence», «следует ли claim из evidence»
и «разумно ли следующее действие по доступному тогда контексту». Их нельзя
свести к одному признаку успеха последнего эксперимента.

## 5. Как использовать для Jev

Начать с коротких эпизодов: доступный префикс сообщений → проверяемый claim →
приложенные результаты → ручная метка и объяснение. Возможные метки:
**поддержан / опровергнут / недостаточно данных / evidence невалидно**, с отдельно
указанной областью вывода. Метки DB и тексты final-answer служат кандидатами для
разметки, а не готовым gold.

Для сравнения следующих действий нужны локальные варианты, например проверить
модельную привязку, объявить готовность, уточнить формулировку или остановить
непродуктивную ветвь. Наблюдаемое выбранное действие не даёт ground truth для
невыполненных альтернатив. Поэтому сначала можно обучать проверку допустимости
и обоснованности, затем отдельно измерять пользу управления поиском.

Split должен сохранять целиком эпизод, parent/child ветви, общие данные,
VSAR134/135 и соседние версии одной гипотезы. Финальные отчёты используются для
последующей аннотации; в контекст более раннего решения будущие результаты не
попадают. Дополнительно нужен тест с целиком отложенным проектом; теперь для
такой проверки доступны четыре разных проекта. Высокая метрика внутри одного
исследовательского журнала ещё не подтверждает перенос на новые задачи.
