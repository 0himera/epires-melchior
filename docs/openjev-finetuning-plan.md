# План дообучения OpenJev и обработки перестановок

Дата: 2026-09-29. Это план эксперимента; обучение и изменения сервинга не запущены.

## Основания

- Текущий checkpoint — `Qwen3_5ForSequenceClassification`, 3 класса:
  contradiction=0, entailment=1, neutral=2. Используется NLI cross-entropy,
  а не генеративный DPO.
- Исходный trainer поддерживает LoRA и сохранение головы `score`.
  В `train_result.json` v5 указан full fine-tune v4 с lr=1e-5, 1 эпохой.
- После численной проверки доступны 258 пар, но ещё требуется исправление
  ролевых ссылок внутри rationale восьми пар — см. дополнение к аудиту.
- Заявленная в model card инвариантность касается порядка списка options
  при неизменном state. Наше сравнение меняет текст state и имена кандидатов:
  это более сильное преобразование, исходный тест его не проверяет.

## 1. Исправить представление кандидатов

Хранить постоянную идентичность кандидата отдельно от отображаемой позиции.
Нормализовать ссылки в rationale до перестановки: собственный кандидат / другой
кандидат. Для уже сохранённых данных восстановить исходную роль через
`generation_swapped`. Ссылки в Python-коде не заменять вслепую.

Перестановка должна одновременно переставлять код, rationale и метки выбора;
применение дважды восстанавливает исходную идентичность. Проверить отдельно:
порядок ключей options, порядок блоков в state, переименование ролей A/B,
повтор идентичного запроса. Не путать эти разные проверки.

## 2. Симметризовать решение при инференсе

Пусть p — нормированная вероятность выбора A при порядке AB;
q — нормированная вероятность выбора A при порядке BA. Во втором порядке
позиция A соответствует исходному кандидату B.

Итоговая оценка исходного A: `s = (p + 1 - q) / 2`.
Итоговая оценка исходного B: `1 - s`.

Это симметричная агрегация при корректном сопоставлении идентичностей;
равенство в пределах численного допуска должно давать неопределённость,
а не победу первой позиции. Четыре NLI-последовательности можно обработать
одним batch вместо нынешних двух; вычислительная работа увеличивается.
Усреднённый score не объявлять калиброванной вероятностью реальной победы.

Проверка на сохранённых, округлённых ответах 14 старых eval-пар дала
10/14 правильных решений вместо 9/14 для каждого отдельного порядка.
Порог не подбирался. Это исследовательский результат на очень малой выборке,
причём seed 5000 содержит проблему ролевых ссылок. Улучшение качества не доказано.

Согласованность после такой агрегации обеспечивается конструкцией и не является
доказательством улучшения модели. Всегда измерять также её ответы до агрегации.

## 3. Данные для пилота

- Восстановить корректные rationale и подготовить оба порядка для каждой из
  258 пар. В каждом порядке есть утверждение о A и о B: всего 1 032 NLI-строки,
  но по-прежнему только 258 независимых сравнений.
- Сначала разделить группы задач примерно 80/20 на train/dev, затем выполнять
  аугментацию. Все позиции, утверждения и повторы одной группы остаются вместе.
- По возможности сохранить пропорции метрик и операторов; не создавать
  иллюзию разнообразия многократным повторением четырёх pathology-примеров.
- Добавить 2–5 тысяч закреплённых примеров из исходного NLI/typed-decision
  корпуса, включая neutral. Начальная доля ML и replay в loss/batch — 1:1;
  это проверяемая стартовая настройка, не установленный оптимум.
- Не использовать наши неопределённые сравнения как NLI neutral: отсутствие
  уверенной эмпирической победы не означает этот семантический класс.

## 4. Обучение

Первый пилот: LoRA только на текстовом backbone, существующая голова `score`
обучается и сохраняется вместе с адаптером; vision остаётся замороженным.
Проверить список trainable-параметров: Qwen3.5 содержит обычное и линейное attention,
поэтому слепой выбор только q_proj/v_proj покрывает не все типы слоёв.

Предлагаемая отправная точка:

- rank=16, alpha=32, dropout=0.05, bf16;
- lr=2e-5, max_length=2048 (проверенные текущие входы <=1264);
- 8 групп ML на эффективный batch, включая обе ориентации;
- checkpoints после 1/2/3 эпох, выбор по dev, несколько training seeds.

Базовый loss — обычный трёхклассовый CE на ML и replay.
Дополнительный эксперимент: `lambda * (p_AB(A) + p_BA(A) - 1)^2`,
начать с lambda=0.1 и сравнить с lambda=0. Это штраф за зависимость от перестановки,
а не замена супервизии победителем. Формула использует одинаковую нормализацию
оценок, как inference. Обе ориентации одной пары должны быть в одном training step.

Не увеличивать вес линейно с raw margin: F1, accuracy, AUC и R² имеют разный
смысл, а большие разрывы часто отражают чрезмерно слабого соперника.
Во время обучения нужно освободить GPU-память занятого vLLM Qwen;
это отдельный шаг при фактическом запуске, сейчас сервисы не менялись.

## 5. Честное сравнение

Сравнить исходный и обученный checkpoint, каждый с обычным и симметричным
решением. Отдельно сравнить LoRA с/без consistency-loss.

Метрики: accuracy в обоих порядках; доля смены выбранного кандидата до
симметризации; абсолютная разница его оценок; API coverage; accuracy/coverage
при неопределённости; качество по метрикам, операторам и семействам;
сохранение качества на отложенной части исходного NLI/typed-decision корпуса.

Существующие 14 eval-пар — набор для разработки. Для окончательного вывода
заранее закрепить новый тест (ориентир 100+ уверенных пар), включить другие
семейства задач/моделей и сопоставимо сильных соперников. Тест не использовать
для выбора эпох, штрафа, порога или состава обучающей смеси. Отчёт с интервалами
по группам датасетов и простыми baseline; небольшие различия не объявлять победой.
